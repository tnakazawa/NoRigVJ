# 007: BPM検出とビート同期

- ステータス: Implemented
- 作成日: 2026-09-14

## 背景・目的

現状のシーンはマイク音声の連続的なレベル(volume/bass/mid/treble)にのみ反応しており、「ドラムの一打」のような瞬間的なビートに合わせた演出ができない。マイク入力からビート(拍)を検出し、各シーンがビートに同期した演出(パルス、フラッシュなど)を行えるようにする。あわせて検出中のBPM(テンポ)をパネルに表示し、VJ現場での目安にできるようにする。

## 要件

### ビート検出アルゴリズム

- 既存の `AudioAnalyzer`([src/audio.ts](../src/audio.ts))が算出している `bass`(低域エネルギー、0-1)を用いる。新たに別帯域を解析する処理は追加しない。
- `bass` の直近の移動平均を保持し、現在の `bass` がその移動平均のN倍(しきい値、実装時にチューニング)を超えたら「ビート発生」と判定する。
- 誤検出防止のため、直前のビートから最小間隔(例: 250ms = 240BPM相当)が経過していない場合は新たなビートとみなさない。

### BPM算出

- ビート発生のたびに、直前のビートとの時間間隔(ms)から `60000 / 間隔` でその場のBPMを算出する。
- 直近数拍(実装時にチューニング、例8拍程度)の移動平均を取り、表示・演出に使うBPM値として安定化する。
- ビートがしばらく(実装時にチューニング、例数秒)検出されない場合はBPM値を0(未検出)に戻す。

### `AudioLevels` への統合

- `AudioLevels`([src/audio.ts](../src/audio.ts))に以下を追加する。
  ```ts
  interface AudioLevels {
    // 既存: volume, bass, mid, treble
    /** ビート発生時に1になり、時間経過で0へ減衰する値(0-1) */
    beatPulse: number;
    /** 検出中のBPM。未検出の場合は0 */
    bpm: number;
  }
  ```
- `beatPulse` はビート発生の瞬間に1になり、その後は時間経過で指数関数的に減衰する(次のビートを待たずに滑らかに0へ近づく)。
- `SceneContextBase`([src/scenes/_shared/types.ts](../src/scenes/_shared/types.ts))は既に `audio: AudioLevels` を持つため、型定義の追加変更は不要(シーン側は `ctx.audio.beatPulse` / `ctx.audio.bpm` としてそのまま参照できる)。

### シーンごとのビート演出

既存4シーンそれぞれに、`beatPulse` を使った演出を追加する(案、実装時に微調整可):

- **Pulse Rings** — ビート発生時にリング1本を新規生成し、外側へ強く弾けさせる。
- **Bar Spectrum** — ビート発生時に全体を一瞬(`beatPulse` に比例して)明るくフラッシュさせる。
- **Noise Field** — ビート発生時にパーティクルの速度・拡散を一瞬強める。
- **Feedback Loop** — ビート発生時に種火の発光強度を一瞬強める。

### UI表示

- 操作UIのパネルに、検出中のBPMを表示する(例: 既存の `#status` 近辺、テキストで `BPM: 128` のように表示。未検出時は `BPM: --` 等)。
- 表示のみで、BPM値を手動で編集・設定する機能は設けない。

## 非機能要件

- ビート検出はマイク入力(`AudioAnalyzer`)が有効な場合のみ動作する。マイク無効時は `beatPulse`/`bpm` とも0のままでよい。
- 既存のシーン切替・カラーパレット・シーンプリセット・クロスフェード・複数投影窓機能は引き続き問題なく動作すること。
- 引き続きオフラインで動作すること。

## 受け入れ基準

- [x] マイク入力に対し、明確なリズム(ドラムのキックなど)があるとビートを検出できる
- [x] 検出したビートに応じて `beatPulse` が1→0へ滑らかに減衰する値としてシーンに渡る
- [x] 4シーンそれぞれに、ビートに反応する演出が加わっている
- [x] 検出中のBPMがパネルに表示され、リズムが安定していればおおよそ妥当な値になる
- [x] ビートが検出されない(無音・非周期的な音)状態でも誤動作せず、BPM表示は未検出表示に戻る
- [x] 既存のシーン切替・カラーパレット・シーンプリセット・クロスフェード・複数投影窓機能は引き続き問題なく動作する

## 実装メモ

- ビート検出・BPM算出は [src/audio.ts](../src/audio.ts) の `AudioAnalyzer` に統合した(`updateBeat()`、private)。別モジュールに切り出さなかったのは、既存の `bass` 値をそのまま使い、状態(直近のbass移動平均・前回ビート時刻・beatPulse・BPM履歴)もこのクラスの中だけで閉じるため。
- しきい値・時定数は要件通り以下で実装(必要に応じて値だけ調整可能な定数として `audio.ts` 冒頭にまとめてある): 最小ビート間隔250ms、bass移動平均の1.5倍超過で検出、bass自体の下限0.05、beatPulseの減衰時定数0.15秒、BPM移動平均は直近8拍、3秒間ビートが無ければBPMを0にリセット。
- `AudioLevels` に `beatPulse` / `bpm` を追加した。`control.ts` 側で強度(`manualIntensity`)を掛けているのは既存の `volume/bass/mid/treble` のみで、`beatPulse`/`bpm` はそのまま(演出の強弱・テンポ表示であり音量ではないため)。
- マイク未接続時のダミー音声(`control.ts` の正弦波モック)は `beatPulse: 0, bpm: 0` 固定とし、ビート検出は行わない。
- シーンごとの演出: Pulse Ringsは`beatPulse`の立ち上がりエッジ(前フレームは閾値以下・今フレームは閾値超え)を検出してリングを1本追加し、追加したリングは自身の経過時間で外側へ弾けながらフェードアウトする(シーンインスタンスのクロージャ内に配列で保持)。Bar Spectrumは`beatPulse`に比例した白フラッシュを重ねる。Noise Fieldは中心からの放射方向にパーティクルを一瞬押し出し、サイズも一瞬拡大する。Feedback LoopはWebGLのuniform `uBeatPulse` をフラグメントシェーダーに渡し、発光(glow)の強さに加算する。
- 実機Chrome(開発サーバー、`window.open`を一時的にスタブ化してこの環境の制約を回避)で、投影窓追加後にPulse Ringsが従来通り描画されること(regressionなし)を確認。ビート検出ロジック自体は、ブラウザのconsoleで`updateBeat()`と同一ロジックを再現し、120BPM相当のキック波形を模擬入力してBPMが正しく120と算出されること、無音区間でbeatPulseが指数関数的に減衰することを確認した(マイク実音でのE2E確認は本セッションの環境では不可のため、ロジック単体の検証で代替)。
