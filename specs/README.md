# 仕様駆動開発ガイド

このリポジトリでは、ある程度まとまった機能追加や変更を行う前に、`specs/` 配下へ仕様書(Markdown)を作成してから実装する。

## フロー

1. **仕様書作成** — `specs/NNN-機能名.md` を `_template.md` からコピーして作成する。`NNN` は3桁の連番(既存ファイルの最大値+1)。
2. **合意** — 「背景・目的」「要件」「受け入れ基準」をユーザーとすり合わせ、`ステータス` を `Draft` → `Approved` にする。
3. **実装** — 承認された仕様書に基づいて実装する。実装中に要件が変わった場合は先に仕様書を更新する。
4. **完了** — 実装が受け入れ基準を満たしたら `ステータス` を `Implemented` にし、必要なら「実装メモ」に補足を残す。

## 対象にする変更

- 新しいシーンの追加、キー操作の変更など、ユーザーが体験する挙動に関わる変更
- 複数ファイルにまたがる設計判断を伴う変更(例: マルチウィンドウ構成、MIDI対応)

タイポ修正や1ファイル内の軽微な修正には仕様書は不要。

## 命名例

- `001-multi-window-projection.md`
- `002-midi-input.md`
