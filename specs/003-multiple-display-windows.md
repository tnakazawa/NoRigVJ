# 003: 複数投影窓・窓ごとの個別シーン対応

- ステータス: Implemented
- 作成日: 2026-09-13

## 背景・目的

現状の投影窓は1枚のみで、全窓が同じシーンを表示する前提だった。もし全ての投影窓が常に同一内容でよいなら、OSのディスプレイミラーリング機能で足りてしまい、アプリ側で複数ウィンドウを管理する意味がない。この機能に意味を持たせるため、**投影窓ごとに異なるシーンを個別に選択・表示できる**ようにする(例: メインスクリーンはPulse Rings、サブスクリーンはBar Spectrum、を同時に投影)。

## 要件

- 投影窓は無制限に追加できる。操作UIの「投影窓を追加」ボタン(既存の「投影窓を開く」から改称)を押すたびに新規ウィンドウが開く。
- 各投影窓は一意のID(`windowId`)を持つ。`window.open()` 時にクエリパラメータ(例: `/display.html?windowId=...`)で渡し、投影窓側は起動時にこれを読み取る。
- **各投影窓は個別にシーンを選択できる。** 強度調整(0〜3倍)とマイク音声解析(`AudioLevels`)は全投影窓・操作UIで共通の1つの値を使う(窓ごとに変えない)。
- BroadcastChannelで配信する状態を、単一の `sceneIndex` から `sceneIndexByWindow: Record<string, number>`(windowId → sceneIndex)に変更する。各投影窓は自分の `windowId` キーの値だけを参照して描画する。自分宛のエントリがまだ無ければシーン0番にフォールバックする。
- 操作UIは開いている投影窓の一覧をリスト表示する。各行に以下を持つ:
  - その投影窓が現在映しているシーンのプレビューcanvas(投影窓の数だけプレビューが並ぶ)
  - シーン選択用のセレクトボックス(`<select>`)
  - 「閉じる」ボタン(`window.close()` で該当投影窓を閉じる)
- 投影窓がユーザー操作で閉じられた場合(一覧の「閉じる」経由か、投影窓自体を閉じた場合か問わず)、操作UIの一覧から自動的に除去される。
- 投影窓が1つも無い状態では、一覧は空のまま(プレビュー・シーン選択も何も表示しない)。「投影窓を追加」ボタンのみ操作可能。
- **既存のキーボード操作のうち、数字キー(1〜3)によるシーン切替は廃止する。** シーン選択は各投影窓行のセレクトボックスのみで行う(「どの窓に対して数字キーが効くか」という曖昧さを避けるため)。強度調整(←/→)とマイク有効化(Space)は全窓共通の値なので、引き続きグローバルなキー操作として残す。

## 非機能要件

- 投影窓の数に上限は設けない(実質的なPCリソースの制約に委ねる)。
- 単一の投影窓だけを開いて使う既存の運用スタイルも引き続き問題なく成立すること。
- 引き続きオフラインで動作すること。

## 受け入れ基準

- [x] 「投影窓を追加」を複数回押すと、その回数分の新規投影窓が開く
- [x] 各投影窓は個別にシーンを選択でき、選択したシーンのみがその窓に描画される
- [x] 強度調整・マイク入力の反映は全投影窓で共通(窓ごとに変える必要はない)
- [x] 操作UI側に投影窓の数だけプレビューcanvasが並び、各窓が現在映しているシーンと一致する
- [x] 一覧の「閉じる」ボタンで該当投影窓を閉じられる。投影窓自体がユーザーに閉じられた場合も一覧から自動的に消える
- [x] 既存のマルチウィンドウ機能(BroadcastChannel同期、フルスクリーン、投影窓なし時の動作)は引き続き問題なく動作する

## 実装メモ

- `windowId` は `crypto.randomUUID()` で生成し、`window.open(url, windowId, features)` の第2引数(ウィンドウターゲット名)にも同じ値を使っている。
- 操作UI([src/control.ts](../src/control.ts))は `displays: Map<windowId, DisplayEntry>` で管理する。`DisplayEntry` は `window`・`sceneIndex`・投影窓専用の `scenes: Scene[]`・専用の `THREE.WebGLRenderer`・プレビュー用canvas2枚・行のDOM要素を持つ。投影窓を追加するたびに `sceneFactories.map(f => f())` で新しいシーンインスタンス一式を生成し、WebGLシーンの `init` もその場で呼ぶ。**[specs/006-scene-crossfade.md](006-scene-crossfade.md)でこの構造は`Layer`([src/layer.ts](../src/layer.ts))という概念に置き換えられた**: `DisplayEntry` は「全シーンの事前生成配列」の代わりに「現在のレイヤー1つ」を持つ形になっている。
- 投影窓の生存確認(`closed` 判定)は `tick()`(Worker駆動、[specs/001](001-multi-window-projection.md)参照)内で全エントリを毎回チェックし、閉じられていたら一覧から自動的に除去する。反復中にMapを変更するため `[...displays]` でコピーしてからループしている。
- 「閉じる」ボタン押下時・自動除去時とも、`entry.renderer.dispose()` でWebGLリソースを解放している(RenderTarget個別のdisposeまでは行っていない)。
- HUD(旧 `#hud`)は「今どのシーンを見ているか」がグローバルに1つでなくなったため廃止。マイク状態・強度・投影窓接続数はパネル側の既存表示(ボタンのラベル、`#status` 等)に統合した。
- 実機Chrome(開発サーバー、`window.open` を一時的にスタブ化してこの環境の制約を回避しつつ)で、複数投影窓の追加・windowIdごとの個別シーン切替・BroadcastChannel経由の反映・「閉じる」ボタンでの除去を確認済み。
- 本文中の「投影窓を追加」「閉じる」などのボタン名は要件定義当時の日本語表記。UIは後日英語化されており、実際のラベルは「Add Display」「Close」(それぞれ [control.ts](../src/control.ts) 参照)。
